# Code of Conduct

## Our Commitment

We want PhosPy to be a respectful, constructive, and inclusive project.

Contributors, maintainers, and community members are expected to help make participation in this project a safe and
positive experience for everyone, regardless of experience level, background, identity, or personal characteristics.

This Code of Conduct applies to all project spaces, including GitHub issues, discussions, pull requests, review
comments, and other public or private interactions connected to the project.

## Expected Behaviour

Examples of behaviour that contribute to a positive environment include:

- being respectful in disagreement and discussion
- assuming good faith and asking for clarification before escalating
- giving constructive, specific, and technically grounded feedback
- being welcoming to newcomers and people still learning
- accepting that others may have different perspectives, priorities, and workflows
- focusing discussion on improving the project
- showing courtesy and professionalism in all project interactions

## Unacceptable Behaviour

Examples of unacceptable behaviour include:

- harassment, intimidation, bullying, or personal attacks
- insulting, demeaning, or inflammatory comments
- discrimination or exclusionary behaviour
- trolling, deliberate provocation, or repeated bad-faith argument
- publishing someone else’s private information without permission
- sexualised language or imagery in project spaces
- sustained disruption of discussions, reviews, or collaboration
- dismissive or hostile behaviour that makes participation unnecessarily difficult

Technical disagreement is normal in software projects. Rudeness, hostility, and contempt are not.

## Scope

This Code of Conduct applies within all official project spaces and whenever an individual is representing the project
or participating in project-related communication.

## Reporting

If you experience or witness behaviour that violates this Code of Conduct, please report it to the maintainers at:

shane @ rededitor dot net

Reports will be reviewed as promptly and fairly as possible. Please include any relevant context, links, screenshots, or
other information that may help with review.

## Enforcement

Project maintainers are responsible for clarifying and enforcing this Code of Conduct.

Maintainers may take any action they judge appropriate in response to behaviour that violates this Code of Conduct,
including:

- requesting that behaviour stop
- issuing a warning
- removing comments, issues, pull requests, or other content
- temporarily limiting participation
- banning a participant from project spaces

Enforcement decisions will be made based on the seriousness of the behaviour, the surrounding context, and the need to
protect the project community.

## Good-Faith Participation

We recognise that open-source collaboration includes critique, review, correction, and disagreement. These are healthy
parts of development when handled respectfully.

Contributors are encouraged to:

- challenge ideas, not people
- explain reasoning clearly
- stay open to evidence and revision
- avoid turning technical discussions into personal conflict

## Final Note

The aim of this Code of Conduct is not to restrict honest technical discussion. It is to set a minimum standard for how
we treat one another while building the project.
