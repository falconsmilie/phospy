# PhosPy 1.5.0 Release Notes

Date: 2026-04-22

## Release Overview

PhosPy 1.5.0 presents the rewrite as a deliberate shipped product rather than a
collection of transitional package reshaping work.

The release is intentionally focused: one analysis-ready dataset boundary, one
supported kinase workflow, and one optional signalome workflow built on the
kinase result. The goal of this page is to explain that supported shape as it
ships in `1.5.0`.

This is a release note, not upgrade guidance. It does not try to preserve old
package narratives or make backward-compatibility promises.

## Supported Product Shape

The supported workflow story in `1.5.0` is:

1. `DatasetBuildRequest -> AnalysisReadyDatasetBuilder.run(...) -> AnalysisReadyPhosphoDataset`
2. `KinaseWorkflow.run(KinaseWorkflowRequest(...))`
3. `SignalomeWorkflow.run(SignalomeWorkflowRequest(kinase_result=...))` (optional)

The public namespace story is equally deliberate:

- `phospy` is the small convenience surface for the main dataset and workflow
  entrypoints
- `phospy.api` is the authoritative public namespace for requests, configs,
  results, references, enums, and public exceptions

The result is a package with a smaller, clearer supported surface and less
ambiguity about where public contract types live.

## Scientific Scope and Parity Posture

PhosPy 1.5.0 is scientifically explicit about what it does and does not claim.

This release does **not** claim blanket equivalence with legacy PhosR behavior.
Instead, it makes bounded, evidence-backed claims at the supported seams:

- scientific confidence is fixture-backed and described lane by lane
- the core L6 kinase scoring and prediction lane is parity-gated for ranking
  behaviour on explicit like-for-like comparison surfaces
- supported lanes that intentionally changed contract are described as
  contract-changed lanes rather than presented as broad legacy-equivalent
  parity

That posture is deliberate. The release aims to be trustworthy about current
scientific support, not larger in scope than its evidence base.

## Bundled Reference Scope

Bundled runtime reference support in `1.5.0` is intentionally narrow and should
be read that way.

In this release:

- bundled runtime references are rat-only
- `ReferencePreset.AUTO` resolves bundled references for the rat lane and
  requires `dataset.organism`
- human and mouse execution require a caller-supplied `ReferenceBundle`
- broader enum presence does not, by itself, imply bundled runtime support or a
  broader science claim

This keeps the shipped package honest about what is bundled versus what remains
caller-supplied.

## Notable User-Facing Improvements

The main user-facing themes in `1.5.0` are:

- a clearer supported package shape around dataset build, kinase execution, and
  optional signalome execution
- clearer public API boundaries between the top-level convenience surface and
  the `phospy.api` authority surface
- narrower default exports in prediction-related areas so stable imports are
  easier to identify
- repaired and governance-locked L6 ranking parity gates on explicit
  like-for-like surfaces
- cleaner alignment between release framing, parity documentation, validation
  documentation, and public contract documentation

These themes are intentionally release-facing. They are more important here
than the internal restructuring work that helped produce them.
