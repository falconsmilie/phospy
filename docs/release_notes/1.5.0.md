# PhosPy 1.5.0 Release Notes

Date: 2026-04-22

## What 1.5.0 Is

PhosPy 1.5.0 is the release where the rewrite is presented as a focused,
supported product contract: one analysis-ready dataset boundary and one
supported workflow chain (`build -> kinase -> optional signalome`).

This page describes the shipped `1.5.0` contract as-is. It is intentionally
not upgrade guidance or backward-compatibility framing.

## Supported Product Shape

The supported workflow story in `1.5.0` is:

1. `DatasetBuildRequest -> AnalysisReadyDatasetBuilder.run(...) -> AnalysisReadyPhosphoDataset`
2. `KinaseWorkflow.run(KinaseWorkflowRequest(...))`
3. `SignalomeWorkflow.run(SignalomeWorkflowRequest(kinase_result=...))` (optional)

Public namespace roles are explicit:

- `phospy`: curated convenience surface for entrypoint executors and the final
  dataset type
- `phospy.api`: authoritative public namespace for requests, configs, results,
  references/enums, and public exceptions

## Scientific Scope and Parity Posture

The `1.5.0` scientific scope is explicit and intentionally bounded:

- science claims are seam-level and fixture-backed, not blanket
  legacy-equivalence claims
- core kinase scoring/prediction in the supported L6 lane is parity-gated for
  ranking behavior on explicit like-for-like surfaces
- contract-changed lanes are documented as contract changes, not described as
  broad legacy-equivalent parity

## Bundled-Reference Scope

Bundled runtime reference support in `1.5.0` is intentionally narrow:

- bundled runtime references are rat-only
- `ReferencePreset.AUTO` resolves bundled references for the rat lane and
  requires `dataset.organism`
- human and mouse execution require a caller-supplied `ReferenceBundle`
- enum presence is broader than bundled runtime support by design and is not,
  by itself, a bundled-science support claim

## Notable User-Facing Improvements

Main release themes for users:

- clearer public API shape and import boundaries (`phospy` convenience surface
  plus `phospy.api` authority surface)
- narrowed prediction package defaults to stable exports, with advanced helpers
  imported from concrete modules
- repaired and governance-locked L6 ranking parity gates on explicit
  like-for-like surfaces
- aligned release messaging across changelog, parity governance, and contract
  docs
