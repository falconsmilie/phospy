# PhosPy 1.5.0 Release Notes

Date: 2026-04-22

## What 1.5.0 Is

PhosPy 1.5.0 presents the rewrite as a focused product: one analysis-ready
dataset boundary and one supported workflow chain from dataset build to kinase
analysis and optional signalome analysis.

This release emphasizes clarity and trust:

- clear public contract shape
- explicit scientific support boundaries
- explicit reference-data boundaries

This page describes the shipped `1.5.0` contract. It is not a migration guide
for older public surfaces.

## Supported Product Shape

PhosPy 1.5.0 supports this workflow chain:

1. `DatasetBuildRequest -> AnalysisReadyDatasetBuilder.run(...) -> AnalysisReadyPhosphoDataset`
2. `KinaseWorkflow.run(KinaseWorkflowRequest(...))`
3. `SignalomeWorkflow.run(SignalomeWorkflowRequest(kinase_result=...))` (optional)

Public namespace roles in this release:

- `phospy`: small convenience surface for workflow executors and the dataset
  boundary type
- `phospy.api`: authority namespace for public requests, configs, results,
  enums/references, and public exceptions

## Scientific Scope and Trust Posture

PhosPy 1.5.0 stands behind the current rewrite science contract for supported
lanes, with evidence and governance tracked in parity and validation docs.

Practical interpretation for this release:

- Science claims are seam-level and fixture-backed, not blanket
  legacy-equivalence claims.
- The core kinase scoring/prediction lane is parity-gated for ranking behavior
  in the supported L6 lane on explicit like-for-like comparison surfaces.
- Contract-changed supported lanes are intentionally documented as contract
  changes, not described as legacy-equivalent behavior.
- Scientific support statements are tied to active tests and documented
  boundaries.

## Reference Scope

Reference support in 1.5.0 is intentionally explicit:

- bundled runtime references are rat-only in this release
- `ReferencePreset.AUTO` requires `dataset.organism` and resolves bundled
  references for the rat lane
- human and mouse execution require a caller-supplied `ReferenceBundle`
- enum availability is broader than bundled runtime support by design;
  enum presence alone is not a bundled-science support claim

## Notable Release Improvements

User-facing improvements in 1.5.0 include:

- clearer public API shape and import boundaries (`phospy` convenience surface
  plus `phospy.api` authority surface)
- cleaner prediction package surface: stable default exports only, with
  advanced helpers imported from concrete modules
- repaired and governance-locked ranking parity surfaces for the supported L6
  lane, with explicit threshold bars in test support files
- stronger alignment between release messaging, parity governance, and contract
  documentation
