# Parity story

This repository uses two parity layers, and they do not carry the same evidential weight.

## 1. Synthetic parity

The synthetic fixture path lives under `tests/fixtures/r_reference/` and is generated by:

```bash
Rscript scripts/generate_r_fixtures.R
```

What it is good for:

- deterministic preprocessing checks
- phosphosite correction checks
- site-matrix construction checks
- sanity checks for the currently implemented downstream wrapper flow

What it does **not** prove:

- broad downstream numerical equivalence to all of PhosR
- full equivalence for unported methods such as motif scoring, kinase prediction, or signalome analysis

This layer is best treated as logic-level parity evidence.

## 2. L6 parity

The richer fixture path lives under `tests/fixtures/r_reference_l6/` and is generated by:

```bash
Rscript scripts/generate_r_l6_fixtures.R
```

It uses the bundled PhosR rat L6 myotube example data and exercises a more realistic downstream kinase-analysis path.

What it is good for:

- weighted kinase activity parity checks
- KSEA score parity checks
- kinase target count parity checks
- checking the implemented downstream analysis on a realistic PhosR example path

This is the strongest current evidence for parity of the downstream methods that are already implemented in Python.

## Current honest claim

Today, `phospy` is best described as a Python package for PhosR-style preprocessing and downstream kinase-analysis summaries, backed by R-generated parity fixtures.

It is **not** yet a full Python replacement for PhosR. Narrow Python-native seams now exist for profile scoring and motif-frequency scoring, but full `kinaseSubstrateScore()` orchestration and score-to-prediction parity remain outside the current claim.

In particular, the following still remain outside the current parity claim:

- a full native Python `kinaseSubstrateScore()` replacement
- a native Python `kinaseSubstratePred()` replacement
- a native Python `Signalomes()` replacement

## Maintenance rule

When behaviour changes intentionally:

1. update the Python tests
2. regenerate the affected R fixtures
3. commit fixture changes with an explanation of what changed and why

That keeps the parity story explicit instead of accidental.


## Prediction trace export

The L6 fixture generator now also writes R-side prediction traces under `tests/fixtures/r_reference_l6/prediction_trace/`. These files are not parity assertions by themselves; they exist to let you compare the PhosR `substrateList()` and `multiAdaSampling()` behaviour directly against Python-side debug traces for selected kinases.

By default the trace export targets `PRKAA1` and `MAPK1`, but you can override that from the command line:

```bash
Rscript scripts/generate_r_l6_fixtures.R --trace_kinases PRKAA1,MAPK1 --trace_top_n 10
```

The generated trace files are:

- `trace_candidates.csv`
- `trace_initial_negatives.csv`
- `trace_iteration_probabilities.csv`
- `trace_iteration_samples.csv`
- `trace_final_ensemble_predictions.csv`
- `trace_final_ensemble_top.csv`

Those files are the starting point for debugging remaining prediction-stage ranking gaps without guessing where the divergence is being introduced.
